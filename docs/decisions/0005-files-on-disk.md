# 0005: Files live on disk, not in the database

Status: Accepted

## Context

Items and locations have photos, and items have receipts and manuals. A
household could accumulate thousands of images.

## Decision

Photos and files are stored as ordinary files in the data directory, under
`attachments/`. The database stores each file's path and details, never its
bytes. Stored file names are generated by the app, never taken from the
uploaded name.

## Why

- The database stays small, so copying it for a backup or before a
  migration is quick.
- Files can be served and resized without loading them through the
  database.
- Generated names remove a whole class of path and filename attacks.

## Cost

- The database and the files can disagree if one is restored without the
  other. Backups therefore always copy the whole data directory together.
- Deleting a record does not delete its file automatically; the app has to
  do both, and restoring a deleted item needs the file still to be there.
